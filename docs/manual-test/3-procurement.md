# Skenario Manual Testing — Procurement

## Ruang lingkup dan prasyarat

Cakupan menu aktif **Procurement**: **Purchase Request**, **Purchase Order**, dan **Goods Receipt**. PR diajukan ke approval workflow; setelah disetujui sistem menghasilkan PO untuk item yang membutuhkan PO, dikelompokkan berdasarkan vendor. GR dibuat dari PO yang telah dikirim atau dari PR approved untuk item tanpa PO. GR yang diposting memperbarui progres sumber dan memicu integrasi stok untuk produk consumable; produk ASSET masuk antrean Registration.

Siapkan akun requester, approver aktif, purchasing/gudang dengan permission yang sesuai, workflow `PURCHASE_REQUEST` aktif untuk company/departemen uji, serta master company/dept/branch, produk, UOM, vendor aktif, service type, gudang (Location bertipe `warehouse`/`gudang`) dan sublokasi bila diuji. Data contoh konkret: `QA-PAPER-01` (Consumable, UOM `PCS`), `QA-LAPTOP-01` (Asset), vendor `QA-VEND-01`, service type `SRV-CLEAN`, branch `JKT`, warehouse `QA-WH-01`, sublokasi `QA-RACK-A1`. Seeder project tidak menyiapkan seluruh data ini; lihat [01-persiapan.md](01-persiapan.md).

## Catatan temuan saat membaca kode

1. **Asset terkait pada item jasa yang memerlukan aset tidak dapat dipilih.** `PurchaseRequest/Create.vue` menetapkan daftar asset kosong, dan drawer menampilkan placeholder **Data asset belum tersedia** serta peringatan bahwa item jasa terkait asset belum dapat dilengkapi. Skenario pembelian jasa seperti service laptop/AC yang memerlukan aset ditandai belum dapat dijalankan lewat UI.
2. Mark Approval manual PR hanya bisa dilakukan oleh requester pemilik atau Administrator, mewajibkan komentar dan dokumen signed, lalu menyelesaikan seluruh level workflow sekaligus. Approval normal tetap dapat dilakukan level-by-level melalui **My Approval**.
3. PR item tanpa PO dapat diterima langsung dari PR setelah PR approved; item yang membutuhkan PO harus melalui PO. PO yang dibuat otomatis dikelompokkan per vendor.
4. GR draft belum menambah saldo. Saat GR diposting, observer membuat integrasi untuk setiap item consumable dengan accepted quantity > 0; quantity mode membuat movement masuk pada gudang/sublokasi terpilih, serial mode menunggu input serial pada Inventory. Produk Asset diarahkan ke Registration.
5. Sisa penerimaan dihitung berdasarkan kuantitas diterima baik (accepted), sehingga jumlah ditolak tetap terbuka untuk penerimaan/penggantian berikutnya.
6. Daftar PR/PO menyediakan pencarian, filter status, pagination dan print. Goods Receipt menyediakan pencarian client-side, filter jenis/status, pagination client-side, riwayat dan print; tidak ditemukan ekspor Procurement.
7. Data PR draft memakai nomor sementara `DRAFT-...`; nomor final dibuat saat submit. Setelah approval final, PO dibuat otomatis jika ada item requires PO.
8. Tidak ada data workflow, produk, vendor, UOM, dan gudang yang siap otomatis dari `DatabaseSeeder`; workflow harus dibuat manual agar submission dapat diuji.
9. Tidak ada kode yang diubah. Jika ada perbedaan hasil aplikasi dari ekspektasi skenario, catat pada kolom Hasil aktual dan buat temuan terpisah.
